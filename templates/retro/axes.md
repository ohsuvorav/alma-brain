# Claude retro: axes register

The living register of recurring friction between the user and the assistant. The daily retro adds evidence here, and each axis ends with an action that compounds: a rule, a memory, a skill, a hook, a workflow or an eval.

- Status: `proposed` → `applied` (live) → `watching` (applied, checking that it holds) → `closed`.
- Evidence is `session-id-prefix date: quote`. Daily files are in [daily/](daily/).
- Signal counts come from keyword matches over typed messages. Read them as trends, not exact numbers.

| # | Axis | Signal | Action | Type | Status |
|---|---|---|---|---|---|
| A | Clarity: dense answers, jargon, % without a base | | R1–R4 | rules | applied |
| B | Verification: claims not checked against the source | | R5–R8, R18 | rules + eval | applied |
| C | Scope: over-engineering, nagging questions | | R9–R11 | rules | applied |
| D | Autonomy: handing back work a tool can do | | R12–R13 | rules | applied |
| E | Writing: length, duplication, language of deliverables | | R14, R15, R20 | rules | applied |
| F | Park and resume: "log it, I'll circle back" | | `park` skill | skill | applied |
| G | Batch decisions: "go one by one" | | `tinder-review` skill | skill | applied |
| H | Long runs: subagent and job status | | R16, R19 | rules | applied |
